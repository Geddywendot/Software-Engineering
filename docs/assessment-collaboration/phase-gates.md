# Phase Completion Gates

Each **Phase** (four weeks) ends with a **Practical Examination** that must be passed before learners can proceed to the next phase.

## Examination Components (per learner)
1. **Conceptual Quiz** – 15 multiple‑choice / short‑answer questions covering the week’s theory.
2. **Coding Challenge** – Implement a small, self‑contained program that applies the core concepts of the phase.
3. **Debugging Exercise** – Given a broken codebase, identify and fix the defects.
4. **Technical Explanation** – Write a 500‑word description of a key architectural decision made during the phase.
5. **Practical Project** – Extend the phase’s project (e.g., add a feature to the CLI or API) and demonstrate it works end‑to‑end.

## Grading Scale
| Score | Outcome |
|-------|---------|
| 85‑100 % | Pass – learner proceeds to next phase. |
| 70‑84 % | Conditional Pass – learner must redo the **Coding Challenge** within one week. |
| < 70 % | Fail – learner must retake the **full examination** (all components) before moving on. |

## Retake Instructions
- Open a new GitHub **issue** titled `Phase X – Retake – Learner‑Y`.
- Submit a new PR with the revised artefacts on a branch named `retake/learner‑Y/phase‑X`.
- The issue must reference the original examination issue.
- Instructors will review and update the grade.

All examination artefacts (quiz answers, code, explanations) are stored in the learner’s personal assessment branch (e.g., `assessment/learner-2/phase-2`).
