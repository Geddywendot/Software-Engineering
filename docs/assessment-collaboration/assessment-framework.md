# Assessment Framework

The following grading structure applies to **each learner individually** throughout the 24‑week programme.

| Component | Weight |
|-----------|--------|
| Weekly practical assignments | 20 % |
| Programming challenges | 15 % |
| Projects (Project 2‑5, Capstone) | 25 % |
| Technical explanations (written) | 10 % |
| Testing and debugging activities | 10 % |
| Final independent examination | 20 % |
| **Total** | **100 %** |

### Marking Rubric (per component)
- **Exceeds expectations (90‑100 %)** – Complete, clean, well‑documented code; tests pass with full coverage; insightful explanation; innovative solution.
- **Meets expectations (70‑89 %)** – Correct solution; minor style issues; adequate tests; reasonable explanation.
- **Partially meets (50‑69 %)** – Works with bugs or missing edge cases; limited testing; explanation lacks depth.
- **Does not meet (< 50 %)** – Does not compile/run; major gaps; no testing; missing deliverables.

### Assessment Instructions
1. **Submit** all artefacts (code, docs, journal entries) via a dedicated **assessment branch** (e.g., `assessment/learner-1/week-07`).
2. **Create an issue** titled `Assessment – Learner‑X – Week‑Y` and link the PR.
3. **Peer review** is required: another learner provides feedback and a grade suggestion.
4. **Instructor final grade** is recorded in the issue comment.

### Retake Policy
- Learners may submit a **single retake** for any component within two weeks of the original deadline.
- The retake replaces the original grade if higher; otherwise the original grade stands.
- Re‑assessment must be opened as a new issue referencing the original.
