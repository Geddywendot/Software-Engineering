# Week 24 – Capstone Evaluation, Documentation and Final Examination

## A. Week overview
- **Week number:** 24
- **Week title:** Capstone Evaluation, Documentation and Final Examination
- **Phase:** Month 6 – Capstone Development and Engineering Evaluation
- **Estimated hours:** 18‑20 h
- **Difficulty:** Advanced
- **Prerequisites:** Week 23 (Testing, Security, Docker and Deployment) completed.

## B. Learning objectives
- Conduct a comprehensive code review and post‑mortem analysis of the capstone project.
- Prepare professional documentation (architecture, API specs, user guide, maintenance plan).
- Perform a final performance and security audit.
- Deliver a polished presentation and demo of the project.
- Reflect on the learning journey and identify areas for continued growth.

## C. Detailed syllabus
| Day | Topics |
|-----|--------|
| 1 | Post‑mortem methodology – what went well, what could improve. |
| 2 | Writing a project retrospective report. |
| 3 | Final documentation checklist – API docs, user manual, deployment guide. |
| 4 | Conducting a security audit report (OWASP, dependency scanning). |
| 5 | Performance benchmarking – load testing with `k6` or `locust`. |
| 6 | Preparing a slide deck and live demo script. |
| 7 | Peer demo session – practice presenting and answering questions. |
| 8 | Final code quality audit – lint, static analysis, type checking. |
| 9 | Grading rubric review and self‑assessment. |
|10 | Live capstone presentation (recorded) and submission. |
|11 | Course wrap‑up – career advice, portfolio building. |
|12 | Celebration and next steps.

## E. Practical laboratories
### Beginner
1. Draft a 1‑page retrospective using the template provided.
### Intermediate
2. Run a baseline load test against the deployed app and record latency metrics.
### Challenge
3. Produce a security audit report summarising findings from week 23 scans and any additional manual tests.
### Independent implementation
4. Create a polished slide deck (Google Slides or PowerPoint) covering problem statement, architecture, demo, and lessons learned.

## F. Weekly assignment
**Problem statement:** Deliver the final capstone deliverables.
- **Deliverables:**
  - Updated repository with all documentation (`README.md`, `ARCHITECTURE.mmd`, `SECURITY.md`, `PERFORMANCE.md`, `RETROSPECTIVE.md`).
  - Recorded 10‑minute presentation video (hosted on YouTube unlisted) with live demo.
  - Final performance report (load test results, bottleneck analysis).
  - Final security audit summary.
- **Constraints:**
  - Documentation must render correctly on GitHub.
  - Video link must be included in the repository `PRESENTATION.md`.
- **Acceptance criteria:**
  - All artefacts present, clear, and pass peer review.
  - Presentation video demonstrates full end‑to‑end workflow.
  - Grading rubric (provided by instructor) yields ≥ 80 %.

## G. Assessment
| Item | Weight |
|------|--------|
| Conceptual Q&A (evaluation methodology) | 15 % |
| Documentation completeness & quality | 30 % |
| Presentation and demo effectiveness | 25 % |
| Performance & security audit reports | 20 % |
| Peer review feedback incorporation | 10 % |

**Rubric highlights**
- Clear, comprehensive docs (15 pts).
- Professional presentation (15 pts).
- Evidence of performance tuning (10 pts).
- Robust security report (10 pts).
- Reflection and growth plan (5 pts).

## H. Completion gate
Submit the final GitHub repository URL and the YouTube video link. All CI checks must pass.

## I. Weekly retrospective
1. What was the most valuable skill you gained during the capstone?
2. Which part of the project would you prioritize for future improvement?
3. How did the feedback loop (peer review, instructor) shape the final product?
4. What are your next steps to turn this project into a portfolio piece?
